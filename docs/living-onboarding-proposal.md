# 新家生活标签：沉浸式需求引导草案

目标：像第一次使用 App 时选择个人兴趣一样，逐步建立「新家的生活画像」。每屏一个主题，用大卡片、数字步进器和多选标签，避免一次铺开几十个下拉框。

## 建议节奏：5 个核心主题 + 4 个选填主题

完成核心问题后即可生成布局；选填主题可在此时或之后补充。页面明确标记「核心」「选填」「还剩几步」，允许返回修改且不丢答案。不要把系统默认值当成用户已确认的答案。

| 主题 | 级别 | 交互与内容 |
| --- | --- | --- |
| 谁一起住 | 核心 | 人数标签；双人床／单人床需求；儿童；是否保留客人过夜的可能 |
| 怎样花预算 | 核心 | HK$0／3,000 以内／3,000–6,000／6,000–10,000／自定义；预算是否含运输与安装；现在买／可以分批买／暂时不买；接受二手的程度 |
| 怎样工作、学习和吃饭 | 核心 | 不在家办公／偶尔／每天；同时使用书桌的人数；卧室／客厅／独立书房；平日用餐人数、招待人数 |
| 谁需要更方便的动线 | 核心 | 无特别需求／长者／轮椅／婴儿车；按选择展开通行、床边活动和地面需求，允许「暂不确定」 |
| 什么最重要、什么必须留下 | 核心 | 只选一个首要目标：收纳／开阔／工作／待客／低预算／多保留旧家具；最多两个次要目标；对已扫描家具标记「必须留下／可以替换／考虑出售」 |
| 给爱好和收纳留空间 | 选填 | 阅读／咖啡／乐器／投影／运动／手作等；每项可设希望预留的面积；衣物／书籍／厨具／运动器材／行李箱等收纳类别 |
| 宠物也有自己的位置 | 选填 | 不养／猫／狗／鸟／其他及数量；按种类展开猫爬架、抓板、窝、卫生区、饮水区、笼架、用品收纳等标签 |
| 房子可以怎样改 | 选填 | 自住／租住；打孔、上墙固定、固定柜体、改墙面等分别允许／不允许／待确认 |
| 喜欢什么样的家 | 选填 | 暖木色／浅色／深色／彩色；木材／布艺／金属等材质；用图片小卡片表达风格，提供「没想好，先帮我搭配」 |

## 交互规则

- 核心问题使用单选卡片、计数控件和少量补充项；多选标签显示勾选状态，不能只靠颜色区分。
- “最重要”与“也想要”分开，防止全部需求都被标成最高优先级。
- 只展开相关问题：选了猫才展示猫用品；不在家工作就跳过书桌位置；不接受改造就排除需要打孔固定的推荐。
- 用户可以选择「没想好」，但系统应明确显示采用的暂定假设，不能静默替用户作决定。
- 爱好面积同时显示平方米和平方呎；多个区域可共用空间，问卷不直接把所有面积简单相加。
- 不向用户索取精确住址；出售安排可先填写地区及可自取时间。

## 示例屏：家里有宠物吗？

第一层：`没有` `猫` `狗` `鸟` `其他`。

选择 `猫` 后，再出现：`猫爬架` `猫抓板` `猫砂区` `饮水区` `晒太阳的位置` `用品收纳`；用户可增加自己的标签。Demo 用预设规则联动，不称为实时 AI 搜索结果。未来接入检索时，区分系统建议与用户确认项。

## 完成页：我的新家需求卡

用一张可编辑摘要呈现，例如：

> 两人生活 · 需要双人床 · 偶尔留客过夜 · 两人同时办公 · 添置预算 HK$6,000（不含运输安装）· 接受二手 · 租房不可打孔 · 养一只猫 · 必须保留沙发与书桌。

提供「修改」「补充选填」「生成布局」三个动作。保存布局时一并保存这张需求卡。

## 哪些答案真正影响方案

- 硬约束：必须保留的家具、床位需求、预算上限、禁止打孔、无障碍需求。
- 排序偏好：空间优先级、风格、材质、二手接受度。
- 补充记录：爱好和宠物细节、搬家时间、自取安排等。

当前是三套预设布局 Demo，应明确提示哪些需求被用于排序、哪些仅记录待后续完善。出现冲突时说明取舍，例如「双人办公需要腾出次卧，但你要求保留单人床」，不伪称所有条件都已满足。无障碍、固定安装及宠物设施仍需实际尺寸与人工复核。
